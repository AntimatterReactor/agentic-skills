# Lessons from RecItDown

Written in the `agent-learn` entry format (that skill's `scripts/lint_learnings.py` validates it). Evidence is the RecItDown repo at 2026-11-05: commit SHAs, or doc sections in `AGENTS.md` / `CLAUDE.md` / `SCHEME.md`. `Source: inferred` entries are lessons drawn from the history, not statements anyone made; they carry a recheck.

## Process and docs

### DO: fix the app name and applicationId before the first install that holds real data
- **When:** scaffolding any app that the owner will install on their own device
- **Why:** RecItDown was SimpleMoney, then PocketSift (fc77351), then RecItDown (d330288), and its package moved from `com.example.simplemoney` to `com.antimatterreactor.recitdown` in a 71-file commit (142f6dc). The phone's real data stayed in the old install and had to move by Backup, Restore, then uninstall.
- **Evidence:** 142f6dc; CLAUDE.md > Repo hygiene and phone state
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: write the pitch, principles, and non-goals before building features
- **When:** starting a product, and again before any large module
- **Why:** a credit-card module (cycles, payments, minimum rules, its own tab) was built 2026-09-17 to 2026-10-12 and removed on 2026-10-21 by the pivot (426e3d4: +297/-2287, plus a migration that deletes user rows). The pivot doc (SCHEME.md) came after.
- **Evidence:** bb65931, 58e507f, 2e4da56 vs 426e3d4, a264c47
- **Source:** inferred
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05
- **Recheck:** if a later project built a big module its owner later cut, confirm a written non-goals list would have caught it

### DO: run each milestone as plan commit, code commits, docs-done commit
- **When:** any feature that spans several commits
- **Why:** the docs always say what is done and what is open. M6 went `1d127f1` (plan) → `6ca98de`, `13928c4`, `6075a87` (code) → `bab3d6d` (docs: code done, permissions, policy).
- **Evidence:** git log 2026-11-01; SCHEME.md milestone list with dated status
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: update AGENTS.md in the same commit as the change that makes it wrong
- **When:** changing architecture, build commands, schema version, or a convention
- **Why:** the agent docs are the next session's only map. AGENTS.md changed in 24 commits and CLAUDE.md in 14, and each doc names itself "verified against the tree".
- **Evidence:** AGENTS.md header; git log --follow churn (TODO.md 32, AGENTS.md 24, CLAUDE.md 14)
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: tag known problems as bug, trap, or smell and delete them when fixed
- **When:** you find something wrong that you are not fixing now
- **Why:** an untagged list reads as noise. RecItDown's "Known oddities" tags each item and says fixed items are deleted, so "everything here is still open".
- **Evidence:** CLAUDE.md > Known oddities
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DONT: treat generated comments and tests as the spec
- **When:** the code was largely produced by another model or has no human review history
- **Why:** CLAUDE.md warns that most of the codebase was generated by DeepSeek, that some tests lock in questionable behavior, and that "fixing" a test to match code (or code to match a test) hides intent.
- **Instead:** confirm intent with the owner before changing either side
- **Evidence:** CLAUDE.md > Provenance: read the code skeptically
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DONT: edit a section the owner marks human-only
- **When:** a doc has a "NEVER TOUCH" or human-only block, such as TODO.md's Human section
- **Why:** it is the owner's task list, not a shared one; ticking items is not the agent's call
- **Instead:** leave it alone and report items you think are done
- **Evidence:** CLAUDE.md > TODO.md
- **Source:** user
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: supersede a stale design direction instead of appending to it
- **When:** a plan or direction doc changes
- **Why:** on 2026-10-21 AGENTS.md said "leaving Material Design: no M3E, no Material You" (7f1b7d9); on 2026-10-29 M4c kept M3 Expressive and dropped only Material You (b066567). An agent that trusted the first would avoid components the app still uses.
- **Instead:** edit the old line, state the date and reason, and re-read the doc's other mentions
- **Evidence:** 7f1b7d9, b066567, SCHEME.md M4
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

## Data

### ANTIPATTERN: destructive migration fallback for a version that has shipped
- **When:** a Room schema changes and the app is on a real device
- **Why:** DROP and recreate wipes the owner's ledger
- **Instead:** a real `Migration` and a `MigrationTest` that builds the old database from its exported schema JSON
- **Evidence:** AGENTS.md > Persistence; 426e3d4; MigrationTest
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```kotlin
.fallbackToDestructiveMigrationFrom(true, 1, 2)          // only versions that never shipped
.addMigrations(Migration3to4(context), Migration4to5, Migration5to6, Migration6to7, Migration7to8)
```

### DO: export Room schemas and commit them
- **When:** the first Room commit, and every schema bump
- **Why:** migration tests build the previous database from `app/schemas/.../<n>.json`; without the file there is nothing real to test against
- **Evidence:** app/schemas/com.antimatterreactor.recitdown.AppDatabase/4..8.json; CLAUDE.md > Testing migrations
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: keep old migrations that create what a later migration drops
- **When:** removing a feature whose tables once shipped
- **Why:** a user on v3 or v4 must still walk the chain; `Migration3to4` and `4to5` still create the credit tables that `5to6` removes
- **Evidence:** AGENTS.md > Persistence; AppDatabase.kt
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: tell the owner to back up before a build that adds a migration
- **When:** installing a build over a phone that holds real data
- **Why:** migrations cannot be downgraded; CLAUDE.md warns that the phone's first launch of a current build walks its real data up the chain and that 5→6 deletes all credit rows (ledger rows stay)
- **Evidence:** CLAUDE.md > Repo hygiene and phone state
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### PATTERN: every entry point initialises process-wide state itself
- **When:** adding a shortcut, widget, receiver, or any component that can start a cold process
- **Why:** `MainActivity` is not guaranteed to run first; reading `Pro.isPro` or settings before `load` returns defaults
- **Evidence:** ShortcutActivity.kt (`Settings.load(this)`); PresetWidget.async; AGENTS.md > Pro ("call `Pro.load` in any entry point that reads it")
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    Settings.load(this)          // before anything reads settings
```

### ANTIPATTERN: mutable process-wide `object` for screen state
- **When:** a keypad, form, or editor keeps its state in a Kotlin `object`
- **Why:** `CalcEngine` is an `object` with `var s`; a rotation or recreation wipes the typed amount and two sheets would share it
- **Instead:** instance state in the fragment, or a `ViewModel`; keep pure math in a stateless function
- **Evidence:** CLAUDE.md > Known oddities (UI layer)
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```kotlin
object CalcEngine { var s = "" }     // shared across every sheet; reset by onViewCreated
```

### DONT: store money as `Double`, or reference related rows by label, in a new project
- **When:** designing the schema
- **Why:** RecItDown's currency is cosmetic (per-row currency ignored by totals) and accounts/categories are label strings, so every rename must rewrite transactions, presets and budgets by hand
- **Instead:** integer minor units (or `BigDecimal`) and ids, unless the owner has a reason to keep labels
- **Evidence:** CLAUDE.md > Known oddities (Data layer); AGENTS.md > Persistence
- **Source:** inferred
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05
- **Recheck:** if the owner confirms the label design was deliberate (backup/CSV simplicity), downgrade this to a trade-off note

### DONT: let the entitlement travel in backups
- **When:** adding a Pro/purchase cache
- **Why:** restoring a backup or a device transfer would grant Pro without a purchase
- **Instead:** exclude the prefs file in `backup_rules.xml`, `data_extraction_rules.xml` (cloud and device-transfer), and the app's own JSON backup
- **Evidence:** 6ca98de; res/xml/backup_rules.xml
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

## Build and test

### DO: build and test with the Linux Gradle wrapper only, through root scripts
- **When:** developing on WSL or Linux
- **Why:** one daemon, one cache, one render environment; the first scripts shelled out to `cmd.exe` and Android Studio's JBR and were replaced on 2026-10-21
- **Evidence:** c852e02; AGENTS.md > Building
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### PATTERN: device-free loop with Robolectric, Roborazzi goldens, and a text view dump
- **When:** a Views or Compose app where an agent must check UI without a device
- **Why:** it checks screens in seconds, produces cheap text evidence, and gates intended changes behind visible golden diffs
- **Evidence:** 1adec30; scripts/loop.sh; ScreenTest.kt
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```
scripts/loop.sh  →  :app:verifyRoborazziDebug  →  FAIL <Class.test> / DIFF <golden> n%  +  app/build/screen-dumps/<screen>.txt
```

### DONT: record Roborazzi goldens outside the canonical environment
- **When:** `scripts/loop.sh --record`
- **Why:** rendering differs per host, so goldens would diff on the next machine
- **Instead:** record in WSL only, view the new PNGs, then commit them
- **Evidence:** AGENTS.md > Dev loop
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DONT: open the compare PNG before reading the failure text and view dump
- **When:** a golden verify fails
- **Why:** images are the costly evidence; the text and dump usually explain the diff
- **Instead:** read the failure message, then `app/build/screen-dumps/<screen>.txt`, then the PNG only if unexplained
- **Evidence:** AGENTS.md > Dev loop
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DONT: drive the owner's phone over adb to check logic
- **When:** verifying anything beyond a layout, colour, icon, or animation change
- **Why:** it is slow and token-heavy, and it writes test rows into real data
- **Instead:** run the loop and build the APK, then give the owner a short numbered list of what to try and what they should see
- **Evidence:** CLAUDE.md > Testing on the phone: tell the user, don't drive it
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DONT: put real user data into screenshots, videos, or fixtures
- **When:** making store images, demos, or tests
- **Why:** the owner's real ledger and a real CSV export sit next to the code; they must never appear in assets or in git
- **Instead:** seed demo data (`StoreShotsTest`), record on a separate install, and `git add` explicit paths
- **Evidence:** docs/media-plan.md > Hard rules; CLAUDE.md > Repo hygiene
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

## UI

### DONT: write unqualified `?attr/colorBackground`
- **When:** reading the theme background in XML
- **Why:** it does not compile; other tokens such as `colorSurface` do
- **Instead:** `?android:attr/colorBackground`
- **Evidence:** AGENTS.md > Repo-specific gotchas
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: apply the accent overlay before `super.onCreate` in every activity
- **When:** adding an activity to an app with user-selectable themes
- **Why:** the project rule is "before `super.onCreate` in every activity"; an activity that skips it renders with the base palette instead of the user's accent
- **Evidence:** Settings.applyAccent; AGENTS.md > Design direction
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    Settings.applyAccent(this)       // before super
    super.onCreate(savedInstanceState)
```

### ANTIPATTERN: shadows on a full-height bottom sheet
- **When:** a modal sheet that fills the screen and must open fast
- **Why:** window and sheet shadows made the open animation GPU-bound on the owner's phone, and the full-height sheet hides them anyway
- **Instead:** a theme overlay with `windowElevation` and sheet `elevation` at 0, `skipCollapsed`, one expand animation
- **Evidence:** 0f57c06; themes.xml `ThemeOverlay.RecItDown.AddRecordSheet`
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```xml
<style name="ThemeOverlay.RecItDown.AddRecordSheet" parent="ThemeOverlay.Material3.BottomSheetDialog">
    <item name="android:windowElevation">0dp</item>
```

### DO: size text from the M3 type scale and icon buttons at 48dp or more
- **When:** writing layouts or code-built views
- **Why:** the project maps text to M3 text appearances (`PageUi.type` in code) and grew header icon buttons to 48dp in 56b642d; widget `RemoteViews` keep `sp` sizes on the same scale
- **Evidence:** 56b642d; AGENTS.md > Repo-specific gotchas
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

## Release and money

### DONT: commit, print, or paste the keystore or its passwords
- **When:** any release work
- **Why:** losing or leaking the upload key means a Play reset or a compromised app
- **Instead:** keep `keystore.properties` and the `.jks` gitignored and outside the repo; read them only through Gradle
- **Evidence:** CLAUDE.md > Repo hygiene; .gitignore
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: make the release script refuse to build without its secrets and keys
- **When:** adding `release.sh` or CI
- **Why:** an empty licence key makes purchases never unlock, so Google refunds them; a missing keystore produces an unsigned build
- **Evidence:** release.sh; 5175e4d
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```bash
[ -f keystore.properties ] || { echo "keystore.properties is missing" >&2; exit 1; }
grep -qsE '^playLicenseKey=.+' gradle.properties ~/.gradle/gradle.properties || exit 1
```

### DO: bump versionCode for every Play upload
- **When:** building an AAB for any track
- **Why:** Play requires an increasing code (re-check the current rule); RecItDown went to 2, 3, 4 across three commits
- **Evidence:** 5175e4d, ed3c80e, d959d94; scripts/release_gate.py checks history
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: keep R8 rules for enums that are stored by name
- **When:** enabling minify on an app that persists enum names (DB, JSON backups)
- **Why:** renamed constants would corrupt reads of old rows and backups
- **Evidence:** app/src/main/keepRules/app.keep
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

```
-keep enum com.antimatterreactor.recitdown.** { *; }
```

### DONT: paywall backup, restore, import, export, or erase
- **When:** deciding Free versus Pro
- **Why:** SCHEME.md principle "Fair free tier": data safety is never paywalled
- **Instead:** gate caps and extras only; on losing Pro, freeze (no new items past the cap), never delete or hide
- **Evidence:** SCHEME.md > Principles and M6
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: update the privacy policy and Data safety answers in the same milestone as a new SDK or permission
- **When:** adding Play Billing or any library that merges permissions
- **Why:** Billing 9.x added INTERNET and ACCESS_NETWORK_STATE; the policy's "no internet permission" claim became false
- **Evidence:** bab3d6d; docs/privacy-policy.md; docs/store-listing.md > Data safety
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: send migrations and billing changes through Play internal testing first
- **When:** shipping either to production
- **Why:** SCHEME.md M7: later updates go through internal testing first, and migrations and billing always do; neither can run in the dev loop
- **Evidence:** SCHEME.md > M7
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05

### DO: set up Git LFS before the first binary asset commit
- **When:** adding screenshots, feature graphics, design files, or video
- **Why:** without it, large binaries land in plain history; RecItDown moved them to LFS in adbd566 (store shots, feature graphic, `*.figcraft`, `*.mp4`, `*.mov`)
- **Evidence:** adbd566; .gitattributes
- **Source:** observed
- **Scope:** skill:mobile-dev-setup
- **Added:** 2026-11-05
